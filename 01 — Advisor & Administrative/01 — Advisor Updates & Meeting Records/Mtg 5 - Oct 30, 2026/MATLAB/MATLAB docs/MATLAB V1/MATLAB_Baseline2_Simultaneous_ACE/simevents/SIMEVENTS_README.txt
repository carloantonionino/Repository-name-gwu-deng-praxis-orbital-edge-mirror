HOW TO RUN IT
-------------
1. Open MATLAB. Change the current folder to this one.
2. Type:

       run_simevents

That prepares the inputs, builds ACE_GroundVsEdge.slx, simulates it, and
checks every result against the verified engine. It ends with PASS or FAIL.

To run a different replication:

       run_simevents(3)

To open the model and look at it:

       open_system('ACE_GroundVsEdge')


WHAT THE MODEL CONTAINS
-----------------------
Two independent paths carrying the same observations under the same link
rules.

  GROUND  generator -> queue -> link -> queue -> ground compute
          -> recorder -> terminator

  EDGE    generator -> queue -> onboard compute -> queue -> link
          -> recorder -> terminator

Ground transmits the full volume and then processes on the ground. Edge
processes onboard first, which reduces the volume, and then transmits.
That reversal is the experiment.

Standard SimEvents blocks are used throughout except for the link, which
is a custom block. See below for why.


THE LINK BLOCK
--------------
LinkWindowServer.m is the one piece a stock block cannot do.

The Excel rule is that a transmission may only begin inside an up window
and must fit inside what remains of that window. If it does not fit, it
waits for the start of the next up window and goes then.

A standard Entity Gate does not behave that way. It would let a
transmission begin and then cut it off when the window closed, which gives
different numbers. LinkWindowServer holds one entity at a time, works out
the wait for a usable window at the moment the entity reaches the head of
the queue, and holds it for that wait plus the transmission time.

Its Capacity property must stay at 1. The link is a single server. A larger
value lets transmissions overlap and the queueing disappears.


TWO THINGS WORTH KNOWING
------------------------
1. The arrival times and per entity service times are written into the
   Entity Generator block actions as literal numbers, at 17 significant
   digits so each value round trips exactly. They are not read from files
   while the model runs. SimEvents compiles block actions with MATLAB
   Coder, which does not permit workspace lookups or calls out to ordinary
   functions, so this is the only reliable way to replay a fixed trace.
   Rebuilding with run_simevents regenerates those numbers from the data
   files, so the data files remain the source.

2. The three custom blocks run in interpreted execution rather than
   generated code. That is set in each class through getSimulateUsingImpl
   and is what allows the recorder to collect results.

IF IT FAILS
-----------
A count mismatch means the stop time is too short or the generator made the
wrong number of entities. Both are reported plainly.

A latency difference of roughly 140 s, or of 720 s, points at the link
window. A window wait is the time left in the current up window plus the
whole down window, not just the down window. Check UpWindow, DownWindow and
CycleOffset on the LinkWindowServer blocks.

Latencies that are far too low, with little or no queueing, mean a Capacity
somewhere is greater than 1.

Any other error: run_simevents prints the full cause tree, which names the
block and the reason.


SCOPE
-----
This stage reproduces the baseline in SimEvents. Scaling the entity count is
a separate decision rather than a code change, because the cohort is fixed at
the 100 accepted observations inside the bounded UTC window. More entities
means either new ACE data with defensible simultaneity, or resampling the
existing cohort.

All results are simulation output conditioned on the stated assumptions.
They are not measurements and not a research finding.
